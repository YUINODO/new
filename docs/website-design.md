# AIスタートアップ コーポレートサイト 設計書

## 1. 概要

### 1.1 目的
AIスタートアップとしての事業内容・ビジョンを伝え、以下を実現するコーポレートサイト（HP）を構築する。

- 会社・サービスの信頼性訴求（採用・営業・資金調達の名刺代わり）
- 製品/サービス内容の紹介
- 問い合わせ・採用・取材・営業リードの獲得（お問い合わせフォーム）

### 1.2 ターゲットユーザー
- 導入検討企業の担当者（営業リード）
- 投資家・提携先候補
- 求職者（採用候補者）
- メディア関係者

### 1.3 想定規模
- まずは1〜2ページ構成のシンプルなLP型サイトからスタートし、将来的にブログ/採用ページなどを拡張できる構成にする。

---

## 2. サイトマップ

```
/                … トップページ（LP）
/about           … 会社概要・ビジョン・メンバー
/service          … サービス・プロダクト紹介
/news             … お知らせ・ブログ（任意・フェーズ2）
/recruit          … 採用情報（任意・フェーズ2）
/contact          … お問い合わせ（フォーム）
/privacy-policy   … プライバシーポリシー
```

フェーズ1（初期リリース）は `/`, `/about`, `/service`, `/contact`, `/privacy-policy` を実装し、`/news` `/recruit` はフェーズ2で追加する想定。

## 4. お問い合わせフォーム設計

### 4.1 目的
- 営業リード獲得、採用応募、取材依頼、その他問い合わせを一元的に受け付ける。

### 4.2 入力項目

| 項目名 | 必須 | 型 | バリデーション |
|---|---|---|---|
| お問い合わせ種別 | ○ | セレクトボックス | 「サービスについて」「取材・広報について」「採用について」「業務提携について」「その他」 |
| 会社名/団体名 | 任意 | テキスト | 100文字以内 |
| お名前 | ○ | テキスト | 1〜50文字 |
| メールアドレス | ○ | メール | メール形式チェック |
| 電話番号 | 任意 | テキスト | ハイフン可、数値+ハイフンのみ |
| お問い合わせ内容 | ○ | テキストエリア | 10〜2000文字 |
| プライバシーポリシー同意 | ○ | チェックボックス | チェック必須 |

### 4.3 UI/UXフロー
1. `/contact` ページでフォーム入力
2. クライアント側バリデーション（リアルタイムエラー表示）
3. 送信ボタン押下 → reCAPTCHA v3等でスパム判定（後述）
4. サーバー側で再バリデーション
5. 送信完了後、確認画面 or 完了メッセージを表示（`/contact/thanks` へ遷移 or モーダル表示）
6. 送信者へ自動返信メール、管理者へ通知メールを送信

### 4.4 スパム・セキュリティ対策
- Google reCAPTCHA v3 もしくは hCaptcha を導入
- ハニーポット（bot用のダミー項目、CSSで非表示）を併用
- サーバー側でのレート制限（同一IPからの連続送信を制限）
- CSRFトークンの付与（フォーム送信時）
- 入力値のサニタイズ（XSS対策）、メールヘッダインジェクション対策

### 4.5 バックエンド実装方式（選択肢）

| 方式 | 概要 | メリット | デメリット |
|---|---|---|---|
| **A. フォーム送信SaaS**（Formspree, Getform, SSGForms 等） | フロントのみでAPIにPOST | サーバー不要・実装コスト最小 | 月間送信数に上限、外部依存 |
| **B. サーバーレス関数**（Vercel/Netlify Functions, AWS Lambda） | フォームPOST → Function → メール送信（SendGrid/SES等）＋DB保存 | 柔軟・拡張しやすい・自社管理 | 実装・運用コストがA案より高い |
| **C. 自社バックエンドAPI** | Node.js/Python等の自前APIサーバーで受信・保存 | 完全な自由度、他システム連携がしやすい | インフラ運用が必要 |

初期フェーズはスピード重視で **B（サーバーレス関数 + メール送信サービス）** を推奨。将来的にCRM連携（HubSpot、Salesforce等）が必要になった場合はC案へ拡張。

### 4.6 データの保存・連携
- 問い合わせ内容はDB（例: Supabase, DynamoDB等）またはスプレッドシート/CRMに保存
- 個人情報を扱うため、保存先のアクセス制御・暗号化を必須とする
- 保存期間・削除ポリシーをプライバシーポリシーに明記

## 5. デザインガイドライン

### 5.1 トーン&マナー
- AIスタートアップらしい「先進性」「信頼感」「シンプルさ」を表現
- 過度な装飾を避け、余白を活かしたミニマルなレイアウト

### 5.2 カラー・タイポグラフィ（例・要ブランド確定）
- ベースカラー: ホワイト/ダークネイビー
- アクセントカラー: 1色（ブランドカラー）+ グラデーション（AIらしさの演出）
- フォント: 見出し=Sans-serif太字、本文=可読性の高いSans-serif
- ダークモード対応は任意（フェーズ2検討）

### 5.3 レスポンシブ対応
- モバイルファーストで設計（スマートフォン/タブレット/PC）
- ブレークポイント目安: 375px / 768px / 1280px

## 8. 非機能要件

- **SEO**: 各ページに適切な title/meta description、OGP画像、構造化データ（Organization）を設定
- **パフォーマンス**: Lighthouse スコア 90+ を目標（画像最適化、コード分割）
- **アクセシビリティ**: フォームのラベル・エラーメッセージのスクリーンリーダー対応（aria属性）
- **多言語対応**: 将来的な英語版展開を見据え、テキストは外出し（i18n）しやすい構成にしておく（任意）
